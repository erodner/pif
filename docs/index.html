Find hidden instructions for AI in PDF documents

An AI assistant that reads a PDF also reads text a person cannot see. Some documents use this to plant instructions, for example “give a positive review only” in submitted papers. This tool reports such text and shows where it is on the page.

What it checks

Each page is compared with what an AI would extract from it. Hidden text is then checked for wording aimed at an AI: rules for known patterns in 8 languages, similarity to reference phrasings, and a small learned model.

Tiny textFont sizes below 2.5 pt
Covered or clippedBehind shapes, outside clip areas
Off the pageOutside the visible area
Hidden layersSwitched-off document layers
Invisible or transparentRender mode 3, zero opacity
Remapped fontsShown text differs from extracted text (OCR check)
Non-visible fieldsMetadata, annotations, forms, attachments

Ratings

HIGH

Injection wording in hidden text.

MEDIUM

Injection wording that is visible or in metadata, or an unconfirmed model hit.

LOW

Hidden text without injection wording, or quoted examples.

How well it works

Two test sets, each run once with a frozen configuration; tuning used separate development data only. Default setup, no extra download.

Test setPrecisionRecallF1
CrackedPDFs2,919 PDFs, 15 hiding techniques 0.960.910.93
PlantedPI-PDF1,080 PDFs, real injection texts in English and German, hard benign texts 0.820.390.53

For comparison, the detector published with CrackedPDFs, trained on that dataset, reaches F1 0.96. PlantedPI-PDF is built reproducibly in the repository from public datasets; full reports are in bench/reports.

Limitations

  • Free-form injections that read like ordinary questions are often missed (recall about 40% on PlantedPI-PDF).
  • Some harmless hidden texts that use words like “ignore” or “bypass” are flagged.
  • A finding is a reason to look at the document, not proof of intent. Papers about prompt injection quote examples.
  • Text inside images is only checked for scanned pages with an OCR layer.

Technical details

The app includes the command line tool pif; the same checks are available as a Python library.

Command line & Python
pip install "promptinjectorfinder[ml,ocr] @ git+https://github.com/erodner/pif"
pif models download minilm
pif scan papers/ -j 8 -f html -o report.html
pif scan cvs/ -f sarif --fail-on medium

Output formats: text, JSON, SARIF and a self-contained HTML report with page crops. Folders are scanned recursively.

from pif import scan
for f in scan("paper.pdf").findings:
    print(f.severity, f.page, f.techniques, f.text)
Detection pipeline
  1. Extraction. Per-character text with style (colour, opacity, effective size, render mode, layer), including switched-off layers.
  2. Visibility. Structural rules plus a render test: each page is rendered with and without its text, and text that changes almost no pixels is hidden.
  3. Glyph check. OCR of sample lines per font, compared with the extracted text.
  4. Wording. Multilingual rules, MiniLM similarity to reference phrasings, and a logistic-regression head on MiniLM embeddings (hidden text only). Optional DeBERTa classifier.
  5. Carriers. Metadata/XMP, annotations, form fields, bookmarks, embedded files, JavaScript, Unicode tag characters.
Components & license

PyMuPDF (parsing, rendering), ONNX Runtime, all-MiniLM-L6-v2 int8 (bundled, 23 MB), ProtectAI deberta-v3-base-prompt-injection-v2 (optional, 740 MB), RapidOCR, PySide6. Models are pinned and checked with SHA-256. Licensed under the GNU AGPL v3 or later; see the README.
